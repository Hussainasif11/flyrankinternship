Search Intelligence: Content Opportunity Scoring

A practical machine learning study for prioritizing content pages for human review using search-performance signals.

FlyRank ML Internship · Search Intelligence · 2026

Abstract

This project investigates whether search-performance signals can be used to prioritize content pages for human review. The analysis uses the FlyRank internship warehouse and focuses on monthly content-level search data, with March 2026 used as the main working month. A rule-based baseline was compared with a Logistic Regression model using a validation design that was later strengthened by grouping observations by client. The Logistic Regression model produced an F1 score of 0.9444 on the Week-5 random split, compared with an F1 score of 1.000 for the Week-4 baseline, while the client-grouped validation produced an F1 score of 0.9432. The results are treated as measured decision-support evidence rather than proof of causal SEO impact, and the final output is a ranked review queue for human content decisions.

1. Introduction / Problem Statement

Content teams may have many pages that could potentially benefit from review, but reviewer time is limited. A simple priority system can help identify which pages deserve attention first.

The research question for this project is:

Can search-performance signals be used to prioritize content pages for human review more consistently than a simple fixed rule?

The intended decision is not to automatically edit or publish content. Instead, the system is designed to provide a ranked queue that helps a reviewer decide where to investigate first.

2. Data

The project uses the public-safe FlyRank ML Internship dataset. The analysis works with content-level search-performance records and uses hashed identifiers rather than client or page names.

Working window

March 2026 was used as the main working month. A middle month was selected instead of the final warehouse month so that the final outcome window was not used while developing the analysis.

Fields used

Field Purpose
report_date Time context
client_hash_id Grouping and validation
content_hash_id Content-level unit
gsc_impressions Search visibility signal
gsc_clicks Search click signal
gsc_avg_position Search position signal

Rows without the required search data availability were excluded from the main search-signal analysis. Private client names, domains, credentials, raw exports and private queries were not included in the research artifact.

3. Methodology

Unit of analysis

One row represents one content page observation for a reporting period. The analysis focuses on content-level search-performance signals.

Baseline

The Week-4 baseline is a simple rule-based prioritization system. It uses observable search signals to assign a priority score, reason code and action label.

Model

Logistic Regression was selected as the first machine learning model because it is simple, fast and interpretable. The purpose was not to maximize complexity but to test whether a trained model could provide useful performance relative to the baseline.

Validation

The initial Week-5 experiment used a stratified random train/test split. Week 6 then repeated the evaluation using a client-grouped split so that observations from the same client were not mixed across training and evaluation sets.

Validation design F1
Week-5 random split 0.944424
Week-6 client-grouped split 0.943178

Leakage checks

Features were reviewed for information that would only become available after the decision point. Label-derived fields and future-window information were excluded from model inputs.

4. Results

The Week-5 model achieved an accuracy of 0.8972, precision of 0.9050, recall of 0.9875 and F1 of 0.9444 on its evaluation split.

Approach F1
Week-4 rule-based baseline 1.0000
Week-5 Logistic Regression 0.9444

The baseline therefore remained stronger on the original metric. This is an important result rather than a failure: the model did not demonstrate that additional model complexity improved the existing decision rule.

Under client-grouped validation, the Logistic Regression F1 was 0.9432. The relatively small difference between the random and grouped results provides useful evidence that the measured model performance was not entirely dependent on mixing observations from the same client across the split.

Interpretation

The model showed strong recall, meaning that it identified a large proportion of the positive examples in the evaluation data. However, the baseline achieved a higher F1 score, so there is no evidence from this experiment that the Logistic Regression model should replace the baseline.

5. Limitations & Honest Framing

  • The analysis does not establish that changing a page will cause better rankings or traffic.
  • The model score should not be interpreted as a guaranteed content opportunity.
  • The current analysis does not directly measure content quality or search intent.
  • Business importance is not fully represented by the available search signals.
  • The baseline and model were evaluated on a specific experimental setup and should be rechecked on new data.
  • Search performance can change because of factors outside the content itself.

The findings should therefore be described as observed and measured relationships that can support human review. They should not be presented as causal evidence about Google's ranking system or as proof that a particular content change will improve performance.

6. Ranked Recommendations

The final action playbook converts search signals into a ranked review queue. The queue is intended to help reviewers focus their limited time on pages with measurable search signals.

Reason code Action Meaning
LOW_CTR_OPPORTUNITY REVIEW_CTR Review title and search snippet where impressions are present but clicks are relatively low.
LOW_POSITION REVIEW_CONTENT Review content and search intent where visibility exists but average position is relatively weak.
HIGH_OPPORTUNITY MONITOR Keep the page on the monitoring list for human assessment.

Human review

Every recommendation should be reviewed before a content change. The reviewer should consider search intent, factual accuracy, business importance, seasonality, brand risk and the expected effort of the proposed change.

What should not be automated

  • Publishing content changes automatically
  • Deleting or redirecting pages automatically
  • Changing legal or regulated content
  • Changing important business claims without review
  • Declaring a page to be "bad"
  • Guaranteeing an SEO outcome from a recommendation

9. Closing Summary

This project demonstrates a complete small-scale ML workflow: framing a decision, checking the data, building a rule-based baseline, training a simple model, validating it under a stronger split, checking for leakage, and translating the output into human-reviewed recommendations.

The main result is deliberately modest. The Logistic Regression model produced useful measured performance, but it did not beat the existing baseline on F1. The resulting playbook is therefore best treated as a decision-support tool and a starting point for further validation rather than an automated content optimization system.
