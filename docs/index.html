Search Intelligence: Content Opportunity Scoring

Hussain Asif
FlyRank ML Internship

A practical study of using search-performance signals to prioritize content pages for human review.

Abstract

This project investigates whether search-performance signals can be used to prioritize content pages that may deserve further review. I used monthly content performance data from the FlyRank internship warehouse and focused on March 2026 as the main working period. I built a rule-based baseline and compared it with a Logistic Regression model using the same evaluation data. The Logistic Regression model achieved an F1 score of 0.9444 on the random split, while the client-grouped validation produced an F1 score of 0.9432. The results are treated as decision-support evidence rather than proof that changing a page will improve search performance.

1. Introduction / Problem Statement

Content teams can have many pages to review, but not every page deserves the same amount of attention. A simple prioritization system can help reviewers decide where to start.

The question for this project is:

Can search-performance signals be used to prioritize content pages for human review?

The goal is not to automatically change content. The goal is to provide a ranked queue that helps a reviewer spend time on pages with stronger measurable signals.

2. Data

The project uses the public FlyRank ML Internship warehouse release. The analysis works with content-level search-performance data.

The working analysis used March 2026 rather than the final month of the dataset. This avoided using the sealed final month while developing the analysis.

Signals used

  • GSC impressions
  • GSC clicks
  • GSC average position
  • Click-through rate derived from impressions and clicks

Client names, domains, private queries, credentials, and raw private exports were excluded from the published work.

3. Methodology

Baseline

The Week-4 baseline uses search signals to create a ranked action queue. Pages receive reason codes such as:

  • LOW_CTR_OPPORTUNITY
  • LOW_POSITION
  • HIGH_OPPORTUNITY

These reason codes are converted into actions such as REVIEW_CTR, REVIEW_CONTENT, and MONITOR.

Model

I used Logistic Regression as the first trained model because it is simple, fast, and relatively easy to interpret. The purpose was to test whether a simple learned model could provide useful evidence compared with the existing rule-based baseline.

Validation

The initial Week-5 evaluation used a stratified random split. In Week 6, I repeated the evaluation using a client-grouped split to reduce the risk that similar observations from the same client appeared in both training and evaluation data.

Leakage check

Label-derived and future-window information was excluded from the model inputs. The validation work also compared the random split with the client-grouped split to check whether the result depended heavily on the splitting strategy.

4. Results

Evaluation F1 Score
Week-5 Logistic Regression — random split 0.944424
Week-6 Logistic Regression — client-grouped split 0.943178
Week-4 rule-based baseline 1.000000

The grouped validation result was close to the random-split result: 0.9432 compared with 0.9444. This suggests that the model's measured performance did not change substantially under the grouped split used in this project.

However, the Week-4 baseline had a higher measured F1 score in the evaluation performed during the internship. Therefore, the trained model should not be described as outperforming the baseline.

5. Limitations & Honest Framing

This project has several important limitations.

  • The analysis does not establish a causal relationship between content changes and future search performance.
  • The ranking score does not understand content quality or search intent.
  • Business importance is not directly represented in the score.
  • The analysis covers a limited working period rather than proving long-term performance.
  • The baseline's measured score should not be interpreted as evidence that every recommendation is correct.

Therefore, the findings are best described as observed, measured, directional, and decision-support rather than predictive guarantees.

6. Ranked Recommendations

1. Review CTR opportunities

Pages with meaningful impressions and very low CTR can be placed near the top of the review queue. A reviewer can inspect the title, snippet, and search intent before deciding whether a change is appropriate.

2. Review weak-position pages

Pages with search visibility but weaker average position can be reviewed for content relevance, structure, and search intent.

3. Monitor instead of automatically changing

Not every signal requires an immediate change. Some pages should remain under observation until more evidence is available.

Human review

No recommendation should automatically publish or modify content. Reviewers should consider factual accuracy, search intent, business importance, seasonality, and potential risk before making a change.

What should not be automated

  • Publishing content automatically
  • Deleting or redirecting pages automatically
  • Changing legal or regulated content
  • Changing important business claims
  • Guaranteeing an SEO outcome

9. Conclusion

This project showed how search-performance data can be turned into a practical prioritization workflow. The trained Logistic Regression model produced a strong measured F1 score, but it did not beat the Week-4 baseline in the reported evaluation. The client-grouped validation result remained close to the random-split result, which provides some evidence that the measured model performance was not highly sensitive to that split. The final output is therefore best used as a human-review prioritization tool rather than an automated content decision system.
